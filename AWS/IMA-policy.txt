
在 IAM 中 策略 Policy 是什么 ？

                策略 是 AWS 的权限定义书 

                策略决定了 谁 可以访问 AWS 中的那些资源 如 EC2， S3, 数据库等

                        以及 它们可以执行哪些操作 如 只读，删除，启动等


                策略 是 JSON 格式 


常见的策略类型

                1 托管策略 Managed Policies 

                  由 AWS 维护，例如 AdministratorAccess 等 

                2 客户托管策略 

                  自己创建并管理的策略 自定义策略 

                3 内联策略 Inline Policies

                  直接嵌入到 特定用户 或者 角色内部的策略， 删除用户时， 策略也会随之删除

                  适合 一次性，专属于 某个人的权限设置 


权限遵循原则 


                1 最小权限原则 Lease Privilege 

                2 默认拒绝 Default Deny 

                

问题 ：

    给了 EC2 S3 的读取权限，那么为什么还要给 IAM user S3 的读取权限呢 ？


    答案： EC2 拥有的权限是 机器的身份， 而 IAM user 拥有的权限是 人的身份 

          - 操作主体的区别

                       EC2 Instance Profile 是给 EC2上运行的程序 app, 后端代码， 日志使用的 

                       当你的后端程序需要定时把数据上传到 S3 时， EC2必须拥有权限， 要不然应用会报 access denied 


          - IAM User 人的身份 

                     它是给你本人，开发人员，运维人员使用的 

                     当你在本地的电脑上 ，通过 aws cli 或者 web 控制台想查看 S3 里的文件时 ，需要 S3 readonly 权限 


          总之， EC2 的权限是为了让代码自动化运行，而 User 的权限是为了让你能人工干预 


托管/自定义策略 (Managed Policy)：
 
它们在 AWS 中是独立的一级资源（有自己的 ARN）。你可以把它们看作“书架上的书”，
你可以把这本书借给角色 A，也可以同时借给角色 B，还可以借给角色 C。因为它们独立存在，
所以必须有一个唯一的身份证号——ARN。

内联策略 (Inline Policy)：

它们是角色的一部分，像角色的“标签”或“身体的一部分”。
它们没有独立存储在 AWS 的策略库中，
而是直接写在 Role 的属性里。如果你删除了这个 Role，
内联策略也就自动消失了。既然它不是一个独立的个体，
自然就不需要 ARN。         


托管策略 (ARN 方式)：

多对多关系：一个策略可以挂载到多个角色。

集中管理：你在一个地方修改策略，所有关联的角色都会立即获得更新。

内联策略：

一对一关系：它被硬编码在特定的角色中。

私有性：它的权限只属于这个角色。正因为它是“私有”的，AWS 没必要给它生成一个全局可见的 ARN，因为它无法被其他角色引用。
