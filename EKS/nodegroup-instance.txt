
可以在 EKS NodeGroup 直接修改 实例的类型 吗 ？

答案： 不可以

因为在 AWS 底层 API 中，aws_eks_node_group 的 instance_type 参数时不可变属性 immutable 

如果直接在 terraform 代码里修改 会 销毁 旧的 Node Group 并创建新的 Node Group 会直接导致节点Pod 被驱逐 服务停止



安全的修改方案

1 创建新的 Node Group 

  在 terrafrom 代码中 定义一个新的 NodeGroup 命名为 compute-v1 ,并在其中指定 新的 实例的类型

  同时保留旧的 NodeGroup

  根目录 使用模版，在根目录 main.tf 中 代码示例：
  
      module "eks" {
      source  = "terraform-aws-modules/eks/aws"
      version = "~> 20.0"

      cluster_name    = "my-cluster"
      cluster_version = "1.31"

      # 定义节点组
      eks_managed_node_groups = {
        # 旧的节点组
        compute_optimized = {
          min_size     = 1
          max_size     = 3
          desired_size = 2

          instance_types = ["t3.medium"]
          capacity_type  = "ON_DEMAND"
          
          labels = {
            role = "compute"
          }
        }

        # 新的节点组 
        compute_optimized_v1 = {
          min_size     = 1
          max_size     = 5
          desired_size = 1

          instance_types = ["c5.large"]
          capacity_type  = "SPOT" # 可以选择 Spot 实例节省成本

          labels = {
            role = "compute-v1" # 新节点组的标签 label 
              }
            }
           }
        } 


  执行 terraform apply 此时EKS 里会同时存在两组 节点


2 验证新节点

  通过 kubectl get nodes 查看新节点是否已经正常加入集群


3 迁移Pod

  - 自动迁移 ： 

    编辑 deployment.yaml 或者 helm charts values.yaml 文件， 更新标签

    spec:
      template:
        spec:
          nodeSelector:
            role: compute-v1  # 关键点：这里改为你的新标签 


  - 手动排空 ： 标记旧节点不可调度 kubectl cordon <old-node-name>

              驱逐旧节点上的 Pod kubectl drain <old-node-name> --ignore-daemonsets --delete-emptydir-data


4 删除旧的 Node Group

  直接修改 terraform main.tf 代码 

  注释 或者 移除 旧的节点组的相关代码

        # 旧的节点组
        compute_optimized = {
          min_size     = 1
          max_size     = 3
          desired_size = 2

          instance_types = ["t3.medium"]
          capacity_type  = "ON_DEMAND"
          
          labels = {
            role = "compute"
          }
        }
